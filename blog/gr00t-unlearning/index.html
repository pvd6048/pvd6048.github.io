Forgetting a task in GR00T: first unlearning results

After learning tasks A then B, SalUn (lr 3e-5) takes task B from — to — success while task A stays at —. SSD, once fixed to compare against the kept task only, does the same: B falls to — and A stays at —. Gradient ascent, GradDiff and NPO break the policy at every learning rate we tried. And in weight space, none of the methods undoes the learning of B.

Gradient ascent, GradDiff and NPO also reach zero on B, but only because the policy is destroyed: A falls to zero too. Lowering the learning rate does not open a useful window: at 1e-7 nothing is forgotten, and from 3e-7 task A already breaks. The original SSD compared against all data and dampened too few weights to matter; comparing against the kept task only (retain reference) fixes it. One NPO run (lr 1e-6) lost task A instead of task B and is being checked. VLA-Forget ran out of memory on a shared 48 GB GPU and will run on a 96 GB GPU.

Unlearning does not undo learning

Learning task B moved the weights by a vector τB. If unlearning simply reversed that, the model would land back on the retrain oracle, which never saw B. It does not. SalUn removes only — of τB, and the fixed SSD —. Both end up at least as far from the oracle's weights as the model was before unlearning, even though they behave exactly like it.

The direction is not random either. Every update leans slightly against τB (cosine — for SalUn), about a thousand times more than a random direction (—). Learning A and learning B themselves are nearly orthogonal (cosine —).

For comparison, learning B puts — of its change into the action head (the diffusion transformer that outputs arm motions). Gradient ascent, NPO and SSD concentrate their change there; SalUn spreads it the way learning does. Representation-level drift is still being computed.

SalUn removes the behaviour but only part of the knowledge

Rollouts on B fail completely after SalUn, but B's probe loss moves only — to — of the way from the model before unlearning to the retrain oracle. The fixed SSD moves it only — of the way. The policy may still hold much of what it learned on B. That residue is what the stream benchmark's relapse metric is designed to detect.

Limits of these numbers

  • One stream step only (learn A, learn B, forget B). The full benchmark runs a five-task stream with repeated learn and unlearn operations.
  • Each unlearning variant was evaluated with one seed of 50 rollouts. The learning results use two seeds.
  • The run used the code of Nov 11 on an RTX A6000 machine. The cluster runs (96 GB Blackwell and 48 GB MIG slices) have not finished yet.
  • Weight drift is measured; representation drift (feature similarity, policy divergence) failed on the diverged checkpoints and is being recomputed. Ten more low learning-rate variants and VLA-Forget are still to run.
  • Hyperparameters are a first grid (three learning rates or three SSD thresholds), not tuned.
Metric definitions
SR (success rate)
Fraction of 50 simulated rollouts that complete the task within 300 control steps.
Gap to oracle
Mean absolute difference in success rate on A and B between the unlearned model and the retrain oracle (LA, which never saw B). Zero is ideal.
Probe forget ratio
(probe loss on B after unlearning − before) ÷ (oracle's probe loss on B − before). 0 means nothing changed and 1 means B's loss matches a model that never learned B.
Share of τB undone
Minus the projection of the unlearning update onto τB, the weight change from learning B. 100% would mean unlearning exactly reversed it.
Distance to oracle (weights)
‖θunlearned − θoracle‖ ÷ ‖τB‖. 1 is where the model was before unlearning, 0 is the oracle.
Share in action head
Fraction of the update's squared size that falls in the diffusion-transformer action head rather than the backbone layers being trained.
Probe loss
GR00T's flow-matching training loss on 32 fixed frames of a task, with fixed noise, so values are comparable across checkpoints.

Data

Every number on this page comes from these files, computed from the calibration run's evaluation and training logs.

  • unlearning.csv: one row per unlearning variant
  • learning_sr.csv: learning success rates per eval seed
  • learning_probe.csv: probe loss per task during LA and LB
  • unlearning_probe.csv: probe loss during SalUn unlearning
  • references.csv: retrain oracle and pre-unlearning model
  • drift_reference.csv: weight drift of learning A, learning B and a random direction
